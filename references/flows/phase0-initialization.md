# 第0步：初始化与偏好加载

**每次触发SKILL时首先执行：**

## 1. 读取用户偏好

检查 `user-preferences.json` 是否存在
- 存在 → 加载偏好数据，用于后续选项排序、推荐标记、个性化欢迎语
- 不存在 → 使用默认值，首次交互结束后自动创建

偏好数据结构与更新规则详见 → [shared-infrastructure.md](shared-infrastructure.md)

## 2. 快捷入口检测

分析用户的首次输入是否已包含丰富的创作信息（题材、主角、冲突等关键要素）

- 如果信息充足 → 展示提取结果，提供三个选项，**等用户选**：
  - "是的，直接开始规划" → 跳过问答，进入第二阶段
  - "先展示提取的信息让我确认/修改" → 展示配置供确认后进入规划
  - "不，我还是想走一遍问答流程" → 进入第一层问答
- 如果用户说「都要跟我确认」「一章一章审」→ 进入问答或展示已有配置，写作模式锁定 `serial-review`，禁止直接开写全稿
- 如果信息不足，且可以等待用户作答 → 进入第一层问答
- **直接开写**仅在「当前环境确实无法收到下一句用户回复」且用户未要求确认时使用。用户还在对话里时，禁止用「开始写」当借口跳过确认。

## 3. 个性化欢迎

（如有偏好数据）：

> "欢迎回来！基于你之前的创作习惯，我为你做了一些推荐（标记为⭐的选项）。"

## 4. 中断续写检测

扫描 `./chinese-novelist/` 目录下的项目文件夹：

- 查找含 `02-写作计划.json` 且 `status` 为 `"in_progress"` 或 `"validating"` 的项目
- 如果找到未完成项目：
  - 展示项目信息：小说名称、完成进度（X/Y 章已完成）、是否有 `awaiting_review` 章节
  - 若有待审章节：先把该章路径和摘要交给用户审，**禁止**自动写下一章
  - 提供选项：
    - "继续上次创作" → 进入第三阶段，从中断章节继续（`serial-review` 仍须先审待审章）
    - "开始新作品" → 进入第一层问答
- 如果未找到 → 正常进入快捷入口检测或第一层问答
